# Mini Project 4. Model predictive control of an inverted pendulum

The assignment is `mini-project-4.pdf`. The self-contained Simulink model is `inverted_pendulum_mpc.slx`; it includes the nonlinear plant copied from Project 3 and stores the MPC object in its model workspace. The linear prediction model uses the same upright state-space matrices as the Project 3 LQR. The controller receives the four simulated plant states and constrains cart force to ±10 N.

The controller uses a 0.05 s sample time, a 50-step prediction horizon, and a 10-step control horizon. Its output weights are `[2, sqrt(2), sqrt(300), sqrt(10)]`, its force weight is `sqrt(0.5)`, and its force-rate weight is `0.1`. These are MPC block weights, whose cost convention should not be equated directly to the continuous LQR matrices. The 5-degree release does not reach the force limit. The horizon study holds all other settings fixed.

Use MATLAB R2025a with Simulink, Control System Toolbox, and Model Predictive Control Toolbox. Open and simulate `inverted_pendulum_mpc.slx` directly. To rebuild the comparison from the adjacent Project 3 folder, run `build_project4` followed by `validate_project4`. The first script saves and replaces the Project 4 model and results file, but does not save or change Project 3. The second reopens the saved MPC model, checks logged force and solver status, compares prediction horizons, and updates the results file. The scripts store temporary Simulink build artifacts in the system temporary directory.

`project4_results.json` contains matched 30 s LQR and MPC responses, design settings, verification, and the prediction-horizon study. It records the exact integral of the held MPC force over its logged intervals. The LQR effort retains the Project 3 analysis-grid convention. Joint settling requires angle within 1 degree and cart displacement within 0.05 m thereafter. `format_project4_layout.m` arranges the main block diagram; `format_and_verify.m` re-exports it and checks that the response is unchanged.
