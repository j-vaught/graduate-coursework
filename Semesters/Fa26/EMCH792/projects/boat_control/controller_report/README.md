# BlueBoat objective, open loop, and feedback

The study implements cascaded PID, integral-augmented LQR, and integral-augmented pole placement. All methods use a shared causal GNSS/IMU estimate, bounded force allocation, installed M200 inverse mapping, and fixed tuning. The reference is a straight east-going line at 1 m/s surge speed. It is a moving-line controller, not a complete RoboBoat mission stack.

The report now begins with an explicit objective and a visual walkthrough. Recover a straight east-going line from a 2 m northward displacement and hold 1 m/s body-forward speed. The nominal aligned-start illustration, displaced-start failure, full-model paths, motor commands, and crab-heading sketch precede the controller mathematics in an appendix.

This revision adds 39 fixed-trim open-loop runs. The 171 original feedback trials and gains are retained unchanged.

Run from `EMCH792/projects/boat_control`.

```sh
uv sync
uv run python -m blueboat_sim.controller_study
uv run python -m blueboat_sim.open_loop_study
typst compile controller_report.typ controller_report.pdf
uv run python -m unittest discover -s tests -v
uv run ruff format .
uv run ruff check . --fix
uv run ty check .
```

The default study runs three methods, 19 cases, and three paired seeds for 171 trials. It includes four environmental cases, seven full-model ablations/stress cases, and all eight original cumulative fidelity presets. Feedback requires command sampling, so the decision clock is enabled throughout the ladder.

Use `--case` repeatedly to select cases, `--seeds` for paired trials, `--duration` for run length, and the simulator's `--set group.field=value` overrides. `--linear-pwm` substitutes the trim tangent for the inverse M200 compensation while retaining feedback gains. Use separate output/data directories for optional experiments.

```sh
uv run python -m blueboat_sim.controller_study \
  --case full_wind5 --case full_wind10 --seeds 792,793,794 \
  --set flags.sensor_dropout=false \
  --output build/no-dropout --data build/no-dropout/data
```

`data/open_loop.json` retains open-loop configuration/seed records, metrics, plotting samples, and hashes. The fixed command is approximately 1589.9 microseconds to each motor at every 50 Hz decision tick, irrespective of measurements. Full open-loop truth and command records are regenerated in `build/open-loop/`.

`data/design.json` contains matrices, gains, weights, poles, and nominal coefficients. `data/summary.json` records configurations, seeds, source hashes, individual metrics, and aggregates. `data/traces.json` contains representative plotting samples. Per-run full truth CSVs, controller estimates/integrators/requested forces, configurations, metrics, and decision audits are saved under `build/controllers/` and regenerated by the command above.

All figures use Typst with CeTZ/Lilaq and the simulator report's square navy/teal diagram language. Quantitative plots use standard plotting colors. The report sources and JSON inputs are retained; no Python plotting library generates the figures.

The tests verify local design mathematics, feedback timing and limits, and closed-loop behavior. Physical boat identification and validation remain the next source of evidence for the platform assumptions.
