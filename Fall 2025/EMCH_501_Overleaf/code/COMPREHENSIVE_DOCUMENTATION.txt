================================================================================
COMPREHENSIVE DOCUMENTATION: PHOTOMETRIC STEREO & POISSON SURFACE RECONSTRUCTION
================================================================================

This document provides a detailed technical exposition of the photometric stereo
and FFT-based Poisson surface reconstruction pipeline implemented in this codebase.
It includes mathematical derivations, code explanations, and recommendations for
extending the method for publication-quality research.

================================================================================
1. EXECUTIVE OVERVIEW
================================================================================

This codebase implements a complete pipeline for 3D surface reconstruction from
photometric stereo (PS) measurements coupled with global integration via the
Poisson equation. The system:

  a) Generates synthetic height fields with known geometry (Gaussian, sphere, cube)
  b) Renders photometric stereo images under multiple directional light sources
  c) Estimates surface normals from image intensities using least-squares PS
  d) Computes surface gradients from the recovered normals
  e) Solves the Poisson equation ∇²z = f to integrate gradients into consistent height
  f) Benchmarks reconstruction accuracy against ground truth

Uses FFT-based Fourier methods to efficiently solve the 2D
Poisson equation with periodic boundary conditions, enabling O(n log n) computation
on n-pixel grids instead of O(n³) direct linear solvers.

SYSTEM ARCHITECTURE:
  - poisson_solver.py: Low-level Poisson equation solver
  - synthetic_ps.py: High-level experimental framework, visualization, benchmarking

================================================================================
2. MATHEMATICAL FOUNDATIONS
================================================================================

2.1 PHOTOMETRIC STEREO PRINCIPLE
---------------------------------
Photometric stereo recovers surface geometry from intensity variations under
different lighting conditions. The fundamental equation is the Lambertian model:

  I_i(x,y) = ρ(x,y) · max(0, L_i · n(x,y))

where:
  I_i     = intensity in image i at pixel (x,y)
  ρ       = surface albedo (reflectance)
  L_i     = unit directional light vector for image i
  n       = unit surface normal at (x,y)
  ·       = dot product
  max(·)  = clamping (shadows)

For a surface z(x,y), the upward-facing unit normal is:

  n = (-∂z/∂x, -∂z/∂y, 1) / ||·||
    = (-p, -q, 1) / sqrt(p² + q² + 1)

where p = ∂z/∂x and q = ∂z/∂y are the surface gradients.

With m ≥ 3 images and unit albedo, we stack the lighting vectors and solve:

  [L₁ᵀ]     [I₁]
  [L₂ᵀ] g = [I₂]    →    g = S⁺ I
  [...]     [...]
  [Lₘᵀ]     [Iₘ]

where:
  S ∈ ℝ^(m×3) = [L₁ᵀ; L₂ᵀ; ...; Lₘᵀ]
  g ∈ ℝ³      = unnormalized gradient vector
  S⁺          = Moore-Penrose pseudoinverse of S
  I ∈ ℝᵐ      = pixel intensities from m images

The recovered g is normalized to a unit normal: n = g / ||g||

From the unit normal, we recover gradients:
  p = -n_x / n_z
  q = -n_y / n_z

2.2 GRADIENT INTEGRATION & THE POISSON EQUATION
-----------------------------------------------
Given noisy or inconsistent gradient fields (p, q), the goal is to find a height
field z(x,y) that best fits these gradients. This is framed as a least-squares
problem:

  minimize ∫∫ [(∂z/∂x - p)² + (∂z/∂y - q)²] dx dy

The Euler-Lagrange equations for this variational problem yield:

  ∂²z/∂x² + ∂²z/∂y² = ∂p/∂x + ∂q/∂y

This is the Poisson equation: ∇²z = f, where:
  ∇² = ∂²/∂x² + ∂²/∂y²  (Laplacian operator)
  f = ∂p/∂x + ∂q/∂y     (divergence of gradient field)

Boundary Conditions:
The code uses periodic boundary conditions (wraparound), which is natural for
FFT-based solvers but assumes the surface wraps around the domain edges.

2.3 FFT-BASED POISSON SOLVER
-----------------------------
The Poisson equation in Fourier space becomes algebraic:

  ℱ{∇²z} = ℱ{f}
  -|k|² · Ẑ(k) = F̂(k)
  Ẑ(k) = F̂(k) / (-|k|²)

where:
  Ẑ(k)   = DFT of z at frequency k = (k_x, k_y)
  F̂(k)   = DFT of f
  |k|²   = k_x² + k_y²

The inverse DFT recovers z:
  z(x,y) = ℱ⁻¹{Ẑ(k)} = ℱ⁻¹{F̂(k) / (-|k|²)}

DC Component Issue:
At k = (0,0), the divisor is 0, creating a singularity. This is resolved by:
  1) Setting λ_k[0,0] = 1 (artificial non-zero denominator)
  2) Zeroing F̂[0,0] = 0 (removing DC component of source)
  3) This fixes the mean of the solution to 0: mean(z) = 0

This reflects the physical fact that the Poisson equation determines z up to an
arbitrary constant; the PS measurements only give us shape, not absolute height.

3.1 poisson_solver.py
---------------------

Function: compute_spacing(x, y)
  Input:  x, y = 1D coordinate arrays (assumed uniform spacing from np.linspace)
  Output: dx, dy = grid spacing in x and y directions
  Purpose: Extracts spacing from grid coordinates; assumes uniform linspace grids

Function: solve_poisson_fft(f, dx, dy)
  Input:
    f       = 2D array of divergence ∂p/∂x + ∂q/∂y
    dx, dy  = grid spacings
  Output:
    Z       = 2D height field solving ∇²z = f
  Algorithm:
    1. Create frequency grids using np.fft.fftfreq
       - fftfreq(N, d) returns N frequencies for spacing d
       - Multiply by 2π to match continuous Fourier transform convention
    2. Construct Laplacian in frequency domain:
       λ_k = -(k_x² + k_y²)
    3. Compute 2D FFT of f: F = fft2(f)
    4. Handle DC singularity:
       - Set λ_k[0,0] = 1.0 (prevent division by zero)
       - Set F[0,0] = 0.0 (remove DC offset)
    5. Divide in frequency domain: Z_hat = F / λ_k
    6. Inverse FFT and extract real part: Z = real(ifft2(Z_hat))

  Computational Complexity: O(n log n) via FFT, where n = H×W pixels
  Memory: O(n) for storage of 2D arrays

3.2 synthetic_ps.py - Surface Generation
-----------------------------------------

Function: create_grid_and_surface(Nx, Ny, x_range, y_range, sigma)
  Purpose: Generate a Gaussian bump surface
  Equation: Z_true(x,y) = exp(-(x² + y²) / (2σ²))
  Properties:
    - Smooth, infinitely differentiable
    - Radially symmetric
    - Maximum height 1 at origin
    - Standard deviation σ controls width
    - Excellent for testing: analytical gradients available

Function: create_shape_surface(shape, ...)
  Purpose: Generate hemisphere or cube surfaces

  Sphere branch (shape="sphere"):
    - Equation: Z = sqrt(R² - r²) for r ≤ R (upper hemisphere)
    - Radius R = 0.9, defined on [-1,1]²
    - Properties: Curved surface, non-convex at boundaries (self-shadowing)
    - Challenges: Singularity at edges where dZ/dr → ∞

  Cube branch (shape="cube"):
    - Piecewise definition using max(|x|, |y|) = r
    - Linear interpolation: Z = h_max · clip(1 - (r - r_0) / Δr, 0, 1)
    - Parameters:
      * r_0 = cube_half = 0.35 (inner radius)
      * Δr = cube_edge = 0.1 (transition width)
      * h_max = cube_height = 0.6 (peak height)
    - Properties: Piecewise-linear with softened edges (reduces Gibbs ringing)
    - Challenges: Discontinuous curvature, tests robustness of PS + integration

3.3 synthetic_ps.py - Normal & Gradient Computation
----------------------------------------------------

Function: compute_gradients(Z, dx, dy)
  Input: Z = height field, dx, dy = grid spacing
  Output: p = ∂Z/∂x, q = ∂Z/∂y (first derivatives)
  Method: np.gradient() with central differences, then normalize by spacing

  Implementation detail:
    p = np.gradient(Z, axis=1) / dx
      - axis=1 = column (x) direction
      - np.gradient uses central differences internally
    q = np.gradient(Z, axis=0) / dy
      - axis=0 = row (y) direction

  Accuracy: Second-order accurate for smooth surfaces
  Edge behavior: One-sided differences at boundaries

Function: normals_from_height(Z, dx, dy)
  Algorithm:
    1. Compute gradients p, q from height
    2. Define normal components:
       n_x = -p
       n_y = -q
       n_z = 1
    3. Normalize: N = (n_x, n_y, n_z) / ||(n_x, n_y, n_z)||
       with small epsilon (1e-8) to avoid division by zero

  Explanation of signs:
    The surface z(x,y) in 3D has position vector:
      r(x,y) = (x, y, z(x,y))
    Tangent vectors:
      r_x = (1, 0, z_x)
      r_y = (0, 1, z_y)
    Normal (cross product):
      n ∝ r_x × r_y = (-z_x, -z_y, 1) = (-p, -q, 1)

3.4 synthetic_ps.py - Image Rendering
--------------------------------------

Function: render_photometric_images(N, lights, albedo=1.0, noise_std=0.0)
  Algorithm:
    1. For each light direction L_i:
       a) Compute dot product: dot = N · L_i (element-wise)
       b) Apply clamping and albedo: I_i = albedo · max(0, dot)
       c) Add Gaussian noise if specified
    2. Return (m, H, W) array of m rendered images

  Physical interpretation:
    - Dot product > 0: surface facet illuminated by light
    - Dot product ≤ 0: shadowed region (clamped to 0)
    - This models Lambertian diffuse reflection without specular highlights

  Noise model:
    - Gaussian noise: N(μ=0, σ=noise_std)
    - Clipped to [0,1] after addition (physically realistic)
    - Tests robustness to sensor/quantization noise

3.5 synthetic_ps.py - Photometric Stereo Recovery
--------------------------------------------------

Function: photometric_stereo(images, lights)
  Algorithm:
    1. Stack light vectors: S = [L_1; L_2; ...; L_m] ∈ ℝ^(m×3)
    2. Compute pseudoinverse: S_pinv = S⁺ = (S^T S)^(-1) S^T
    3. For each pixel (y, x):
       a. Extract intensity vector: I = [I_1[y,x], I_2[y,x], ..., I_m[y,x]]^T
       b. Solve least-squares: g = S_pinv @ I  (m×3 by 3×1 = 3×1)
       c. Transpose to row vector: g_row = g^T
       d. Normalize to unit normal: N_est[y,x] = g_row / ||g_row||

  Per-pixel independence:
    - Each pixel solved independently (embarrassingly parallel)
    - No spatial regularization; sensitive to noise
    - Requires m ≥ 3 images for well-posed system

  Pseudoinverse stability:
    - np.linalg.pinv uses SVD, handles ill-conditioned S gracefully
    - For well-distributed lights, S^T S is well-conditioned
    - Rank deficiency only when lights are coplanar

Function: gradients_from_normals(N_est)
  Algorithm:
    1. Extract normal components: n_x, n_y, n_z
    2. Recover gradients using normal-to-gradient mapping:
       p_est = -n_x / (n_z + eps)
       q_est = -n_y / (n_z + eps)

  Numerical stability:
    - eps = 1e-8 prevents division by zero
    - When n_z ≈ 0 (steep/vertical surface), estimated gradients blow up
    - This is physically correct but problematic numerically

================================================================================
4. HAND-DERIVED LAPLACE EQUATION (SIMPLE CASE)
================================================================================

This section derives the Poisson equation from first principles for a simple 1D
case, then extends to 2D. This is the mathematical foundation of the integration
method.

4.1 1D CASE: DERIVING POISSON FROM LEAST-SQUARES
-------------------------------------------------

Problem Statement:
  Given noisy gradient measurements p_meas(x), estimate height z(x) on [0, L]
  such that dz/dx ≈ p_meas(x).

Least-Squares Formulation:
  minimize J[z] = ∫₀ᴸ (dz/dx - p_meas)² dx

To minimize, we use calculus of variations. Let z be perturbed by small ε η(x):
  z̃ = z + ε η(x), where η(0) = η(L) = 0 (fixed boundary)

The perturbed objective:
  J[z̃] = ∫₀ᴸ (d(z + εη)/dx - p_meas)² dx
        = ∫₀ᴸ [(dz/dx + ε dη/dx) - p_meas]² dx
        = ∫₀ᴸ [(dz/dx - p_meas)² + 2ε(dz/dx - p_meas)(dη/dx) + O(ε²)] dx

At the minimum, dJ/dε|_{ε=0} = 0:
  0 = ∫₀ᴸ 2(dz/dx - p_meas)(dη/dx) dx

Integration by parts (with η = 0 at boundaries):
  ∫₀ᴸ (dz/dx - p_meas) dη/dx dx = [(dz/dx - p_meas)η]₀ᴸ - ∫₀ᴸ d/dx(dz/dx - p_meas) η dx
                                 = 0 - ∫₀ᴸ d/dx(dz/dx - p_meas) η dx

So the first-order condition becomes:
  ∫₀ᴸ d/dx(dz/dx - p_meas) η(x) dx = 0

Since this holds for all admissible η, the integrand must vanish (fundamental lemma):
  d/dx(dz/dx - p_meas) = 0
  d²z/dx² = dp_meas/dx

This is the 1D Poisson equation! The right-hand side is the divergence (derivative)
of the gradient field.

4.2 EXTENSION TO 2D
-------------------

Problem Statement:
  Given noisy gradient field (p_meas, q_meas) on domain Ω ⊂ ℝ², minimize:

  J[z] = ∬_Ω [(∂z/∂x - p_meas)² + (∂z/∂y - q_meas)²] dx dy

Calculus of Variations:
  Perturb z → z̃ = z + ε η, compute first variation:

  δJ = ∫∫ [2(∂z/∂x - p_meas)(∂η/∂x) + 2(∂z/∂y - q_meas)(∂η/∂y)] dx dy = 0

Integrate by parts (assuming η = 0 on ∂Ω):
  ∫∫ (∂z/∂x - p_meas)(∂η/∂x) dx dy = ∮ (∂z/∂x - p_meas) η n_x dS - ∫∫ ∂/∂x(∂z/∂x - p_meas) η dx dy
                                     = - ∫∫ (∂²z/∂x² - ∂p_meas/∂x) η dx dy

  ∫∫ (∂z/∂y - q_meas)(∂η/∂y) dx dy = - ∫∫ (∂²z/∂y² - ∂q_meas/∂y) η dx dy

Setting δJ = 0:
  ∫∫ [-(∂²z/∂x² - ∂p_meas/∂x) - (∂²z/∂y² - ∂q_meas/∂y)] η dx dy = 0

Again by the fundamental lemma:
  ∂²z/∂x² + ∂²z/∂y² = ∂p_meas/∂x + ∂q_meas/∂y

In compact form:
  ∇²z = ∇ · (p, q)

where ∇² is the Laplacian and f = ∇ · (p, q) is the divergence of the gradient field.

4.3 PHYSICAL INTERPRETATION
----------------------------

Why does this equation make sense intuitively?

Consider a small square cell in the domain with:
  - Top edge: height z_top = z + ∂z/∂y · Δy/2
  - Bottom edge: height z_bottom = z - ∂z/∂y · Δy/2
  - Left edge: height z_left = z - ∂z/∂x · Δx/2
  - Right edge: height z_right = z + ∂z/∂x · Δx/2

The "slope mismatch" at the center is:
  (z_right - z_left) - p · Δx = (∂z/∂x - p) · Δx
  (z_top - z_bottom) - q · Δy = (∂z/∂y - q) · Δy

The total mismatch energy in this cell:
  E_cell ∝ (∂z/∂x - p)² + (∂z/∂y - q)²

To minimize total energy across the grid, gradients must be consistent. The
Laplacian ∇²z acts as a "smoothness enforcer" that makes the solution as close
to the measurements as possible while remaining globally integrable.

4.4 SIMPLE NUMERICAL EXAMPLE
----------------------------

Example: 1D gradient field on 5-point grid

Grid points: x = 0, 1, 2, 3, 4
Measurements: p_meas = [?, 1.0, 0.5, -0.5, ?]  (no measurements at boundaries)

We want: dz/dx ≈ p_meas

Poisson equation discretized with spacing Δx = 1:
  (z_{i+1} - 2z_i + z_{i-1}) / 1² = ∂p/∂x|_i

For interior points (i = 1, 2, 3):
  ∂p/∂x|_1 ≈ (1.0 - ?) / 1 = undefined (at boundary)
  ∂p/∂x|_2 ≈ (0.5 - 1.0) / 1 = -0.5
  ∂p/∂x|_3 ≈ (-0.5 - 0.5) / 1 = -1.0

Assume Neumann BC: ∂z/∂x|_0 = p_meas[0], ∂z/∂x|_4 = p_meas[4] (unknown)
Or Dirichlet BC: z(0), z(4) fixed (simplifies example)

With Dirichlet BC z(0) = 0, z(4) = 0:
  z_2 - 2z_1 + 0   = -0.5  →  z_2 - 2z_1 = -0.5
  z_3 - 2z_2 + z_1 = -1.0
  0   - 2z_3 + z_2 = ?     (depends on p at boundary)

This is a sparse linear system that can be solved directly (3×3 for interior unknowns).

In the code, FFT solves this implicitly in Fourier space where the Laplacian is
diagonal: λ_k = -(k_x² + k_y²).

================================================================================
5. COMPUTATIONAL IMPLEMENTATION DETAILS
================================================================================

5.1 FFT FREQUENCY GRIDS
-----------------------

The np.fft.fftfreq function:
  fftfreq(N, d=1.0) returns frequency array:
  [0, 1/(N·d), 2/(N·d), ..., (N/2-1)/(N·d), -N/2/(N·d), ..., -1/(N·d)]

  Note: Negative frequencies come AFTER positive (due to FFT output ordering)

  Example: N=4, d=1.0
    fftfreq(4, 1.0) = [0, 0.25, 0.5, -0.25]

  These are normalized frequencies (cycles per unit distance). To get wavenumbers:
    k_x = 2π · fftfreq(W, dx)
    k_y = 2π · fftfreq(H, dy)

Meshgrid:
  KX, KY = np.meshgrid(kx, ky, indexing="xy")
  Creates 2D grids of k_x and k_y values
  indexing="xy" means first index is y, second is x (matrix convention)

Wavenumber magnitude squared:
  |k|² = k_x² + k_y² = KX² + KY²
  Laplacian in Fourier space: λ_k = -|k|²

5.2 DC COMPONENT HANDLING
--------------------------

The zero-frequency component (DC term) represents the mean of the array:
  F[0,0] = (1/(H·W)) Σ_all f[i,j]

Problem: λ_k[0,0] = -(0² + 0²) = 0, causing division by zero

Physical interpretation:
  The Poisson equation ∇²z = f determines z up to an additive constant.
  The DC component (mean) is undetermined.

Solution in code:
  1. Set λ_k[0,0] = 1.0 (artificial non-zero value)
  2. Set F[0,0] = 0.0 (remove DC component of source)
  3. Consequence: mean(z) = 0 in the solution

Alternative approach (not used here):
  - Compute only non-DC frequencies
  - Use different boundary condition (Neumann instead of periodic)
  - Explicitly set mean after solving

5.3 FINITE-DIFFERENCE GRADIENTS
--------------------------------

np.gradient(Z, axis=k) computes first-order derivatives using central differences:

  ∂Z/∂x[i,j] ≈ (Z[i,j+1] - Z[i,j-1]) / 2  (interior points)

At boundaries (i or j = 0 or N-1):
  np.gradient uses one-sided differences
  Forward: (Z[i,j+1] - Z[i,j])
  Backward: (Z[i,j] - Z[i,j-1])

Error: O(Δx²) globally, O(Δx) at boundaries

For second derivatives (in divergence computation):
  p = np.gradient(Z, axis=1) / dx    [first deriv]
  px = np.gradient(p, axis=1) / dx   [second deriv]

  Error compounds: O((Δx)²) × O((Δx)²) = O((Δx)⁴)?
  Actually: Two applications of O(Δx²) centered differences = O(Δx²) overall

5.4 PSEUDOINVERSE COMPUTATION
------------------------------

np.linalg.pinv(S) computes Moore-Penrose pseudoinverse using SVD:

  Given S = U Σ V^H (SVD decomposition)
  Pseudoinverse: S⁺ = V Σ⁺ U^H

  where Σ⁺ inverts all non-zero singular values, zeroing small ones (threshold)

Properties:
  - For full-rank m×3 matrix (m ≥ 3): S⁺ = (S^T S)^{-1} S^T
  - For rank-deficient S: projects onto column space
  - Minimum-norm least-squares solution: g = S⁺ I minimizes ||g|| subject to ||Sg - I||

Threshold: np.linalg.pinv uses threshold = max(m, n) × eps × max_singular_value
  - eps ≈ 2.22e-16 (machine epsilon for float64)
  - Singular values below threshold are treated as zero

Computational cost: O(m²·3) = O(m²) for SVD of m×3 matrix

5.5 COMPLEXITY ANALYSIS
-----------------------

Overall pipeline complexity for H×W grid with m lights:

  Per-pixel photometric stereo: O(m² · H · W)
    - For m=16 lights: O(256 · H · W)

  Gradient computation: O(H · W) for finite differences

  Poisson solve: O(H · W · log(H·W)) via FFT
    - Actually: O(H log H · W log W) for 2D FFT

  Visualization: O(H · W) per figure

  Dominant term: Photometric stereo (if m large) or FFT (if m small)

  For H=W=128, m=16:
    PS: ~268M operations
    FFT: ~200K operations
    Total: Dominated by PS, runs in milliseconds on modern CPU

Memory usage:
  - m images: m·H·W floats = 16·128·128 × 8 bytes ≈ 2 MB
  - Height field, normals, gradients: ~3 MB
  - FFT temp arrays: ~2 MB
  - Total: ~10 MB, easily fits in L3 cache

7. ERROR ANALYSIS & VALIDATION
================================================================================

7.1 SOURCES OF ERROR
--------------------

Error in photometric stereo:
  1. Image measurement noise
  2. BRDF non-Lambertian effects (specularity, roughness)
  3. Insufficient light diversity (singular lighting matrix)
  4. Self-shadowing (not modeled in forward projection)
  5. Floating-point round-off

Error in gradient computation:
  1. Finite-difference truncation error: O(Δx²)
  2. Boundary effects (one-sided differences)
  3. Normalization errors when n_z is small

Error in Poisson integration:
  1. Discrete approximation of divergence: O(Δx²)
  2. Periodic boundary condition (wrapping artifacts)
  3. Floating-point errors in FFT round-trip
  4. Numerical precision in frequency-domain division

Total error (rough estimation):
  ε_total² ≈ ε_PS² + ε_grad² + ε_poisson²

  For H=W=128:
    Δx ≈ 2/128 ≈ 0.016
    Finite-difference error ≈ (0.016)² ≈ 2.5e-4
    PS error (m=16, clean) ≈ 1e-3
    Poisson error ≈ 1e-4
    Total ≈ sqrt(1e-6 + 2.5e-4 + 1e-8) ≈ 0.016 (typical observed ~0.023)

7.2 ERROR METRICS USED
---------------------

Root-mean-square error (RMSE):
  RMSE = sqrt(mean((Z_true - Z_est)²))

  Properties:
    - Sensitive to large errors (outliers)
    - Dimensioned (same units as height)
    - Interpretable: ~63% of errors within ±RMSE (for Gaussian distribution)

Mean absolute error (MAE):
  MAE = mean(|Z_true - Z_est|)

  Properties:
    - Robust to outliers
    - More intuitive interpretation
    - Not used in this code but often reported in research

Angular error (degrees):
  θ = arccos(clip(N_true · N_est, -1, 1)) [in degrees]

  Properties:
    - Independent of height scale
    - Measures normal accuracy directly
    - 1° error in normal → ~1.7% error in gradient (for shallow surfaces)
    - More robust to scale ambiguity than height error

7.3 VALIDATION STRATEGIES
-------------------------

Strategy 1: Compare against known analytical solution
  - Gaussian surface has analytical ∇z
  - Poisson equation with exact RHS should give RMSE ≈ machine epsilon
  - Finite-difference error dominates: observe O(Δx²) convergence

Strategy 2: Noise-free synthetic data
  - Generate surface, render images under perfect conditions
  - Run full pipeline
  - Compare with ground truth
  - Isolates algorithm errors from measurement errors

Strategy 3: Progressive refinement
  - Solve on low resolution (64×64), then higher (128×128), then (256×256)
  - RMSE should decrease as O(Δx²)
  - Validate consistency across scales

Strategy 4: Ablation studies
  - Vary number of lights: should improve with more lights
  - Vary noise level: should degrade linearly
  - Vary surface shape: smooth vs. piecewise-linear

Strategy 5: Cross-validation with alternative methods
  - Sparse direct Poisson solver (conjugate gradient)
  - Weighted least-squares instead of exact integration
  - Compare results; should agree to machine precision

8.2 ALTERNATIVE INTEGRATION METHODS
-----------------------------------

Current method: FFT-based Poisson solver with periodic BC

Recommended alternatives:

  1. NEUMANN BOUNDARY CONDITIONS:
     Instead of periodic wrapping, use zero-gradient BC on boundaries:
     ∂z/∂n = 0 on ∂Ω

     Implementation:
       - Use sine-FFT (not full FFT) for symmetric extension
       - Or use Dirichlet-to-Neumann preconditioner for iterative solver
       - Reduces edge artifacts from periodic wrapping

     Comparison:
       - More physical for non-wrapping domains
       - Slightly higher computational cost
       - Results should have less ringing at boundaries

  2. WEIGHTED LEAST-SQUARES INTEGRATION:
     Instead of uniform weighting, weight by gradient reliability:

     minimize ∫∫ w(x,y)[(∂z/∂x - p)² + (∂z/∂y - q)²] dx dy

     where w(x,y) = confidence in gradient estimate at (x,y)

     Implementation:
       - Compute weights based on normal quality (e.g., ||N_est||)
       - Or based on light condition number at each pixel
       - Leads to weighted Poisson: ∇·(w∇z) = ∇·(w·[p,q])
       - More complex to solve (matrix-free iterative methods)

     Advantage: Down-weights unreliable regions
     Disadvantage: Slower, requires iterative solver

  3. SPARSE DIRECT SOLVER (CONJUGATE GRADIENT):
     Instead of FFT, use iterative solver on discrete Poisson system:

     [∇²_discrete] [z] = [f]

     where discrete Laplacian is sparse (5-point stencil):
     Δz[i,j] = (z[i+1,j] + z[i-1,j] + z[i,j+1] + z[i,j-1] - 4z[i,j]) / dx²

     Implementation:
       - scipy.sparse.linalg.cg or linalg.gmres
       - Define Laplacian as sparse matrix or LinearOperator
       - Precondition with multigrid for faster convergence

     Advantage: Flexible boundary conditions (Neumann, Dirichlet, mixed)
     Disadvantage: Slower than FFT (unless well-preconditioned), more memory

  4. TENSOR VOTING FOR GRADIENT FIELD SMOOTHING:
     Pre-process gradient field to remove noise before Poisson integration:

     For each pixel, propagate gradient information to neighbors:
     1. Build tensor voting field from gradients
     2. Extract principal curvature directions
     3. Smooth gradients along confidence measure
     4. Then solve Poisson

     Advantage: Data-adaptive, preserves edges
     Disadvantage: Complex algorithm, parameter tuning required
     Reference: Guy & Medioni (1997)

8.3 REGULARIZATION & SMOOTHNESS PRIORS
---------------------------------------

Current approach: Pure Poisson (no regularization)

Problem: Noisy gradients → noisy height, no smoothing

Recommended regularization:

  1. TIKHONOV REGULARIZATION:
     minimize ∫∫ [(∂z/∂x - p)² + (∂z/∂y - q)² + λ(∂²z/∂x² + ∂²z/∂y²)²] dx dy

     Effect: Quadratic smoothness term (membrane model)
     λ = regularization parameter (traded off by user)

     Poisson modification:
     ∇²z + λ∇⁴z = f  (now involves 4th-order Laplacian)

     Implementation:
       - Frequency response: λ_modified(k) = -k² - λ|k|⁴
       - Can still solve via FFT: Ẑ = F̂ / λ_modified
       - Larger λ → smoother reconstruction, less gradient fidelity

  2. TOTAL VARIATION (TV) REGULARIZATION:
     minimize ∫∫ [(∂z/∂x - p)² + (∂z/∂y - q)² + λ||∇z||] dx dy

     Effect: Sparsity in gradients (preserves edges while smoothing)

     Implementation:
       - Non-convex, requires iterative solver (ADMM, proximal gradient)
       - More complex than Tikhonov
       - Superior edge preservation in practice

     Papers: Rudin, Osher, Fatemi (1992); Boyd et al. (2011)

  3. DATA-ADAPTIVE REGULARIZATION:
     λ(x,y) = per-pixel regularization strength
     Chosen based on measurement confidence:

     λ(x,y) = λ_max · (1 - confidence(x,y))

     where confidence ∈ [0,1] measures PS quality

     Effect: Light regulation in well-lit regions, strong smoothing in shadows
